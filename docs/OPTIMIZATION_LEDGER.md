## Two different "baselines" — do not conflate them

`torch_transformer_benchmark.py` already contains a thing called the baseline:
**`BaselineTransformer`**, the unoptimized reference model. That is what the
harness times the optimized model against, and what the reported speedup is a
speedup *over*. It never changes.

This file's iteration 0 is a different thing: the **start state**, meaning the
optimized tree as it was inherited at the beginning of this optimization run.
It already scored 6.831x over `BaselineTransformer`.

So every row carries two numbers, and they answer different questions:

- **Geomean vs `BaselineTransformer`** — the absolute score, the same number
  the harness prints. **This is the series to plot**: it starts at 6.831x and
  should climb. It is the only column that is comparable across every row.
- **Gain vs previous row** — what this one cycle was worth on its own.

## How to read a row

- **Status** — `Accepted` (in the tree and measured), `Rejected` (measured, then
  `git restore`), `Rejected (Phase 2)` (never built — unsound on this hardware
  or breaks a coverage rule), `Superseded` (a later row replaced it), or
  `Open` (identified, not yet tried — a candidate, not a result).
- **Evidence** — what measurement decided it. A row with no measurement behind
  it is `Open`, no matter how good the reasoning was.

A caution on the absolute column: it comes from a full sweep, and the sweep
re-times `BaselineTransformer` every run, so a few percent of it is the
*baseline* arm moving rather than the optimized one. Where a sweep row
disagreed with the in-process A/B it was re-run, and the corrected value is
what is recorded — see the note on each row.
